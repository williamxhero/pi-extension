# Pi 自动续跑：CPA 监督器

`/loop-to-done` 开启当前会话的监督。开启时，如果当前分支已有任务且会话空闲，就立即检查，无需再发消息。正在运行或有消息排队时，等本轮和队列结束；空白会话则等待首个任务。扩展通过 Pi 的 `cpa/deepseek-v4.1-flash` 调用一个没有工具的监督模型。它不修改主会话的模型，不单独读取文件，不设置次数上限。每个监督判断都是一次额外的模型调用。

| 判断 | 行为 |
| --- | --- |
| 继续执行 | 给主会话一条与当前进展相关的下一步。 |
| 授权执行 | 指明操作为何是完成具体用户要求所必需。只在用户已经委托的范围内批准，不覆盖必须本人确认的门禁。 |
| 换路探索 | 指明不同于失败尝试的可验证路线；有独立工作先做。 |
| 已完成 | 监督模型列出需求和验收记录后停止。单独一句「全部完成」不能作为验收证据。 |
| 硬阻塞 | 列出必须的外部条件、已核查路线及结果、为什么没有其他工作可做、最小恢复条件后停止。 |

前三种以标有 `【续跑监督器】` 的扩展消息触发主会话，不伪装成真人输入。后两种写入可见的会话记录并关闭开关，状态栏区分「已完成」和「硬阻塞」。证据不足的停机请求会改为要求核实，不把模型的自述当作独立的人工验收。

**发送给 CPA 的内容：**当前分支内的用户文本、助手可见回复、近期监督意见，以及工具名和成功/错误标志。摘要请求限制长度，省略工具参数、原始工具输出、附件和思考过程。文本做常见密钥模式的尽力遮盖，并非通用脱敏器；不要在不允许发送到 CPA 的会话中启用。用户需求被截断或依赖未读取的附件时，不会据此直接判定完成或硬阻塞。

**停止与失败：** `/stop-loop-to-done` 取消等待、重试和正在进行的监督调用，不中止主会话已开始的回复。用户发新消息、切换分支、关闭会话或重载扩展会使旧判断失效。手动中止主回复也会关闭续跑。CPA 超时、错误、无法解析或授权缺乏引用时，不发送授权或固定兜底指令；30 秒后退避重试，最长间隔 5 分钟。没有 CPA 模型时也按故障处理。

**安装：**把 `loop-to-done.ts` 放到 `~/.pi/agent/extensions/`，在 Pi 中配置 `cpa/deepseek-v4.1-flash` 后执行 `/reload`。无需为扩展另存密钥。普通会话默认关闭；恢复同一会话保留开关和停止原因，新建或复制的会话不继承开启状态。Pi Web 的 Chat Only 模式不加载扩展。原版 Pi Web 使用状态栏；配套 Web 分叉版的开关在「系统」「工具」右侧。

**验证：**在仓库根目录运行 `node --test extensions/loop-to-done/loop-to-done.test.mjs` 使用隔离 Pi RPC、模拟主模型与 CPA 响应，不使用个人会话或真实模型凭据。
